### 3-4. 本番に入ったかの確かめ方

- `neo_skill` の `.py` を触ったなら画面の印（`アプリ側 neo_skill: xxxxxxxx`）が変わる
- **手元の `python -c` と比べてはいけない** — Windows は CRLF・本番 Linux は LF。git の blob から LF のまま計算する
  （`neo_skill/*.py` を名前順に、`名前 + b'\0' + sha256(blob).hexdigest()` を sha256 に足して先頭 8 桁）
- 本番の画面は iframe の中。`document.querySelector('iframe').contentDocument.body.textContent`

### 3-5. files リポジトリは別セッションと共用

### 3-7. 生成の道が 3 つある（スキル / ベタ打ち / CSV）。**片方を直したら 3 つとも確かめる**

第 4 弾でも、品名の半角（CSV と③は半角・ベタ打ちの一発生成は全角）と、サイドバーの費用（「車検証だけ」の道だけ確かめずに入れていた）が道によって違った。

### 3-8. 金額に効かない欄は検算が守らない — **車種も**

第 3 弾の部品コードに続き、第 4 弾で**車種**が見つかった: vendor は型式指定・類別（KA81）と型式・車台番号（KA06）が**別の車でも** confirmed にする。
1 桁の読み違いでオデッセイの見積がミライースの NEO になり、金額は合うので ✅ 合格だった。いまはアプリが作る前に突き合わせる
（`app._p2n_vehicle_crosscheck`。実機 NEO 4,938 本で空振り 0）。**車種・部品コード・品番のような欄は、実データで答え合わせしてから信じる。**

**止める側の空振りにも同じ注意がいる。** 第 4 弾の 5 周目のレビューで、「候補が 2 車種なら止める」が**正しい入力まで止めていた**ことが分かった:
コグニは同じ車を年式の区切りで別の車種コードに分ける（N-BOX SLASH の J84／J89・N-ONE の J51／J52。2010 年以降で 235 組）ので、
KA81 も KA06 も 2 コードを返す。vendor は初度登録と KA81 の生産期間で 1 つに決める。いまは**型式指定・類別で引けないとき**だけ止める。
**「止める規則」を入れたら、正しい入力の実データで空振りを数える。**

### 3-9. Codex の講評は `-o` のファイルができるまで終わっていない

### 3-10. Codex は起動時に第 2 の脳を読みにいく

### 3-11. **書き換えは Write で .py を作って流す**（heredoc・sed は化ける）

- heredoc の中の `\\n`・`\\u3000`・`'C:\\Users…'` は化ける（9/22 も 2 回踏んだ）。Git Bash の `sed -i` は CRLF を LF にして書き戻す
- 改行の数え方は `git ls-files --eol` か python で（Git Bash の `grep -c $'\r$'` は当てにならない）。記憶 `reference-windows-shell-pitfalls`

### 3-12. 残件・指摘の書き方をうのみにしない

直す前に、いまのコードで本当に起きるのかを確かめる（第 4 弾の C「型式の『改』で車種が決まらない」は、E の実データでは問題なし＝直していない）。

## 5. 今回いちばん大事だった学び

> **「確定」「合格」の印は、それを出した側が何を確かめたかまで見る。**

vendor の confirmed は「2 つの引き方の両方で何かに当たった」だけで、「同じ車に当たった」ではなかった。金額は印字どおりなので検算は通り、

> **テストは「壊すと落ちる」まで確かめて、はじめてテスト。**

9/21 のテストの半分は、直しを元に戻しても通っていた。第 4 弾は足したテストを 87 通り壊して、全部が狙った文言で落ちることを確かめた。
