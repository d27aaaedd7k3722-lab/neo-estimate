### 3-3. テストを足したら「わざと壊して落ちること」まで確かめる

足したあと、対象のコードをわざと元に戻して **FAIL が出ることを目で見る**。

### 3-4. 本番に入ったかの確かめ方

- `neo_skill` を触ったなら画面の印（`アプリ側 neo_skill: xxxxxxxx`）が変わる
- **手元の `python -c` と比べてはいけない** — Windows は CRLF・本番 Linux は LF で必ず食い違う
  （9/21 に 35 分無駄にした）。git の blob から LF のまま計算する
- `app.py` だけ触ったなら印は変わらない → **無条件で出る CSS** を iframe の `<style>` で探すのが速い
- 本番の画面は iframe の中。`document.body.innerText` は 0 になる。
  `document.querySelector('iframe').contentDocument.body.textContent` を使う

### 3-5. files リポジトリは別セッションと共用

`git add` は**パス指定**で行う（`git add -A` は他セッションの作業を巻き込む）。
触る前に `git log --oneline -3` で誰かが進めていないか見る。

### 3-6. app.py は 13,000 行の 1 ファイル

関数を切り出すときに「呼び出し側の参照だけ残る」事故が起きやすい。
対策として pyflakes の `undefined name` を `reg_insurance` の 12a で見ている。
**切り出したら必ず `python -m pyflakes app.py` を通す。**

### 3-7. 生成の道が 3 つある

スキル / ベタ打ち / CSV で決めごとが別実装。**片方を直したら 3 つとも確かめる。**
（税区分の扱い・費用の扱い・調整行の有無がすべて違う。`docs/引き継ぎ書.md` §13-2 の表）

### 3-8. CSS で Streamlit の標準 UI を消すと標準の操作も消える

サイドバーが二度と開けなくなったのがその例。`display:none` を要素まるごとに当てず、**中身を名指しで消す**。
